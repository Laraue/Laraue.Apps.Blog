**API-ключ** — это долгоживущий credential, который позволяет чему-то, кроме веб-приложения или Telegram-бота, действовать от вашего имени: скрипту, задаче CI или AI-агенту вроде Claude, подключённому через [MCP](/ru/blog/documentation/laraue-boards/integrations/mcp). Без пароля, без флоу логина — просто ключ в заголовке.

Ключ — не отдельная, более слабая идентичность. Он может делать ровно то же, что вы сами руками, в той одной организации, для которой был создан — не больше и не меньше. Если вас позже удалят из этой организации или отберут право, любой созданный для неё ключ автоматически теряет его тоже.

## Создание ключа

Откройте **Account → API keys**. Введите название, которое напомнит, для чего этот ключ — «CI», «Claude MCP» — и нажмите **Create key**.

Исходный ключ показывается один раз, сразу после создания. Скопируйте его сейчас: Boards хранит только его хеш, поэтому показать его снова невозможно. Если вы его потеряли — отзовите и создайте новый.

![Вкладка API keys на странице Account: существующие ключи и форма создания нового](https://laraue.com/static/images/blog/docs/laraue-boards/api-keys.jpg)

## Управление ключами

Список API-ключей показывает для каждого:

- **Name** — название, которое вы указали при создании
- **Key prefix** — первые несколько символов, чтобы отличать свои ключи друг от друга без повторного показа полного значения
- **Created** — когда ключ был создан
- **Last used** — последний раз, когда он успешно авторизовал запрос, или пусто, если ни разу

Вы видите и управляете только своими ключами — не ключами, которые создали другие участники организации.

## Отзыв ключа

Нажмите **Revoke** рядом с любым активным ключом. Это действует немедленно: следующий запрос с этим ключом будет отклонён. У отозванного ключа вместо кнопки Revoke отображается **Revoked**, и его нельзя восстановить — вместо этого создайте новый.

## Один ключ — одна организация

Ключ привязан к той организации, в которой вы находились в момент его создания. Если вы работаете сразу в нескольких организациях — например, в своей Personal и в командной — и хотите дать инструменту доступ к обеим, создайте отдельный ключ в каждой.
